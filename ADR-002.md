# ADR-002: Profiles, review documents, and local evidence questions

## Status

Accepted for v0.3.

## Context

Biological repositories differ substantially. A genomics workflow, an SBOL design
library, and a scientific Python package cannot be judged by the same domain rules.
Users also need a portable review document and a way to ask focused questions in
the terminal after cloning a repository.

## Decision

BioRobust will keep a shared evidence/report contract and add named profiles. The
first profiles are `generic`, `genomics`, `genomics-workflow`, and `sbol`; `auto`
uses narrow file/content signals to select one of them. Markdown is the portable
review document, JSON remains the automation contract, and HTML remains the human
browser view. The `ask` command is deterministic and selects existing findings; it
does not call an LLM, make network requests, or execute repository code.

The SBOL profile will report artifact, serialization, version, validation-signal,
and interoperability-signal evidence. It will not claim SBOL semantic validity or
biological design correctness without an explicit future SBOL-aware adapter.

## Consequences

- New biological domains can be added as profiles without changing generic rules.
- Reports remain comparable at the evidence/status level, not as a global quality score.
- Static scans are safe and auditable after a user clones a repository.
- Semantic validation and workflow execution remain future opt-in capabilities.
- The profile registry is an internal extension seam today; third-party entry-point
  plugins should be added only after the rule lifecycle and compatibility contract
  are tested against real repositories.
