# ADR-002: Profiles, review documents, and local evidence questions

## Status

Accepted for v0.3.

The original keyword-based `ask` command is no longer part of the current CLI. It
was removed after pilot use showed that open-ended questions could fall through to
an unfiltered list of findings and appear to be answers. The report workflow and
evidence contract remain active; a better grounded question interface may be
designed later.

## Context

Genomic repositories differ substantially. A workflow, a sequence-analysis tool,
and a scientific Python package cannot be judged by exactly the same domain
signals. Users also need a portable onboarding document and a way to ask focused
questions in the terminal after cloning a repository.

## Decision

BioRobust will keep a shared evidence/report contract and add named profiles. The
profiles are `generic`, `bioinformatics`, `genomics`, and `genomics-workflow`; `auto`
uses narrow file/content signals to select the least-specialized useful profile.
Markdown is the portable onboarding document, JSON remains the automation
contract, and HTML remains the human browser view. The `start` command is the
recommended first pass for understanding and replication planning. The `ask`
command is deterministic and selects existing findings; it does not call an LLM,
make network requests, or execute repository code.

## Consequences

- New biological domains can be added as profiles without changing generic rules.
- Reports remain comparable at the evidence/status level, not as a global quality score.
- Static scans are safe and auditable after a user clones a repository.
- Semantic validation and workflow execution remain future opt-in capabilities.
- The profile registry is an internal extension seam today; third-party entry-point
  plugins should be added only after the rule lifecycle and compatibility contract
  are tested against real repositories.
