# ADR-001: Local-first, evidence-first genomics scanner

Status: accepted

## Context

The project needs to help people judge whether open-source genomic software is robust enough to inspect and reuse. A broad biological quality platform, an execution service, and a static repository scanner are all possible starting points.

## Decision

Start with a local-first static scanner for computational genomics repositories. Use explicit evidence-bearing findings and statuses instead of a single quality score. Focus the first profile on sequencing and variant-calling workflows, with Nextflow and Snakemake as the primary workflow targets.

## Options considered

1. **Hosted execution platform** — richer validation, but substantially higher security, infrastructure, data-governance, and support costs.
2. **Single numeric score** — easy to compare, but hides uncertainty and encourages unsupported certification claims.
3. **Local static evidence scanner** — narrower validation, but safe to run, easy to adopt, and useful before domain-specific execution adapters exist.

## Why this is best now

It gives maintainers immediate value from repository metadata and documentation while preserving a path to later workflow adapters and sandboxed validation. The evidence model makes uncertainty visible instead of pretending that static analysis proves scientific correctness.

## Consequences

The first release cannot prove that a pipeline produces valid biology. It can show whether the repository documents the conditions needed for someone else to investigate that question.

## Revisit triggers

- At least 10 real repositories have been profiled and rule false-positive patterns are understood.
- Users request and can safely support opt-in workflow execution.
- A stable adapter contract exists for trusted workflow engines and reference-data provenance.
