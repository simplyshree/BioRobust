# ADR-003: Broaden the public scope to biological software

## Status

Accepted for v0.4.

## Context

BioRobust began with genomic and bioinformatics repositories, but the core workflow is broader: inspect a local repository, collect evidence about reuse and reproducibility, preserve uncertainty, and produce a reviewable report. The README and product documents understate that general capability by presenting BioRobust as a genomic-only starter scanner.

At the same time, the current domain-specific checks make genomic assumptions about references, sequence inputs, workflow paths, and known-answer validation. Applying those checks to neuroscience, proteomics, imaging, or other biological software would create misleading findings.

## Decision

BioRobust will use `biology` as a broad public profile backed by the existing generic repository checks. The specialized `bioinformatics`, `genomics`, and `genomics-workflow` profiles will retain the current genomic rule pack. The `generic` profile remains the fallback for unrelated scientific and computational repositories.

Automatic selection will choose profiles in this order:

1. `genomics-workflow` when a supported workflow is present.
2. `bioinformatics` when genomic or sequence-analysis signals are present.
3. `biology` when broader biological signals are present.
4. `generic` otherwise.

The CLI and Python scanner will default to `auto`. Existing profile names and rule IDs remain compatible, and no global score will be introduced.

## Options considered

### Keep the genomic-only scope

Pros: smallest change and easiest to calibrate.

Cons: hides the reusable evidence workflow, limits adoption, and conflicts with the actual user vision.

### Apply genomic checks to every biological repository

Pros: broad marketing language with little implementation work.

Cons: produces false findings for non-genomic software and damages trust in the evidence model.

### Add a broad biology profile over generic checks

Pros: honest public breadth, backward compatibility, small implementation surface, and a clear path for future domain adapters.

Cons: the broad profile does not yet provide deep scientific validation for every biological field.

## Why this is best now

It expands the audience without pretending that a static repository scan can validate every kind of biology. Users receive useful repository-level evidence immediately, while specialized rule packs remain explicit and calibratable.

## Consequences

- `biorobust start .` becomes useful for biological repositories that contain no sequence files.
- The report records whether `biology`, `bioinformatics`, `genomics-workflow`, or `generic` was selected.
- The project must document that broad profile detection is not complete domain understanding.
- Future profiles can add domain-specific evidence without changing the generic report contract.
- The public release must include a license, contributor path, and honest launch language.

## Risks and mitigations

- **False-positive markers:** keep markers conservative, test generic fallback, and record the selected profile.
- **Overclaiming:** state that v0.4 provides repository-level evidence, not scientific certification.
- **Rule drift:** retain stable rule IDs and add fixtures before changing semantics.
- **External repository drift:** use external pilots for validation, but keep them out of CI.

## Revisit triggers

- At least 15 pinned repositories across several biological domains have been profiled.
- Users request a dedicated profile with evidence requirements that generic checks cannot meet.
- A maintained plugin contract is needed by external contributors.
- Optional sandboxed execution can be designed with clear security and resource boundaries.
